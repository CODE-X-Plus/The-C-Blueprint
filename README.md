# Architectural Taxonomy & Repository Layout

<h6>Designing a robust, scalable codebase requires a disciplined approach to directory organization and structural modularity. This repository is architected around a clear, progressive proficiency framework, systematically dividing problem sets and capstone applications into distinct tiers to facilitate optimal learning and intuitive code discovery.</h6>
<h6>At the foundation lies the Simple tier (c-beginner-problems/), which focuses on core fundamentals, syntax mastery, control flow, loops, functions, and elementary array manipulation through foundational exercises like prime checking and factorial calculation. Moving up the hierarchy, the Medium tier (c-medium-problems/) introduces intermediate complexities, such as pointers, multi-dimensional matrices, strings, data structures, searching and sorting algorithms, and dynamic memory management.</h6>
<h6>As technical demands scale, the Hard tier (c-hard-problems/) tackles sophisticated data structures, backtracking algorithms, custom memory allocators, graph traversal strategies, and introductory multithreading concepts. Beyond theoretical challenges, the Advanced tier (c-advanced-problems/) delves deep into systems-level engineering, addressing lock-free concurrency, virtual machine architecture, event loops, garbage collection mechanisms, and specialized database indexing.</h6>
<h6>Complementing these problem sets are the Mini Projects (c-mini-projects/), which transition theoretical knowledge into production-ready, real-world applications. Spanning from simple record trackers to complex implementations like a fully-featured POSIX-compliant shell featuring pipes, input/output redirection, and a custom relational database engine, this section serves as the ultimate test of software engineering capability.</h6>
<p align="center">
<img src="https://raw.githubusercontent.com/CODE-X-Plus/The-C-Blueprint/refs/heads/main/Others_files/table1.svg">
</p>
<h6>Together, this structured taxonomy provides a seamless navigation experience for developers, educators, and collaborators exploring the repository. Each directory is meticulously documented and isolated to ensure that contributors can easily locate, test, and extend specific modules without friction, establishing a professional benchmark for systems programming proficiency in C.</h6>

# Beginner Topology & Directory Layout

<h6>The beginner problem set is organized into a clean, intuitive directory topology to ensure seamless navigation and straightforward compilation. Split systematically into two distinct modules—Part 1 (Problems 01–10) and Part 2 (Problems 11–20)—the structure maps directly to foundational programming concepts.</h6>
<h6>Each exercise resides in its own dedicated subdirectory under c-beginner-problems/, named using a consistent, zero-padded numbering convention paired with descriptive identifiers (e.g., 01_hello_world/, 12_leap_year/). Within each directory, individual source files are neatly isolated with clear, standardized naming like hello.c or leap_year.c.</h6>
<p align="center">
<img src="https://raw.githubusercontent.com/CODE-X-Plus/The-C-Blueprint/refs/heads/main/Others_files/table2.svg">
</p>
<h6>This modular arrangement eliminates clutter, allowing developers and reviewers to quickly locate, examine, and test specific source codes without friction. By enforcing strict file naming conventions and hierarchical clarity, this layout establishes a predictable and professional standard for the entire beginner curriculum.</h6>

# Advanced & Intermediate Modules Topology

<h6>Bridging core fundamentals with systems-level engineering, the intermediate and advanced tiers are structured to manage rigorous computational workloads. The repository categorizes these stages into three distinct functional modules. Medium Level Part 1 (Problems 01–10) focuses on algorithmic problem-solving, searching, sorting, and text processing. Medium Level Part 2 (Problems 11–20) builds on this foundation with matrix rotations, linked lists, and dynamic memory tasks under c-medium-problems/.</h6>
<p align="center">
<img src="https://raw.githubusercontent.com/CODE-X-Plus/The-C-Blueprint/refs/heads/main/Others_files/table3.svg">
</p>
<h6>Transitioning to high-performance architecture, the Hard track (c-hard-problems/) covers complex graph traversal, pathfinding, and memory allocators. Simultaneously, the Advanced track (c-advanced-problems/) explores low-level systems programming, featuring non-blocking lock-free queues, custom bytecode virtual machines, high-concurrency epoll servers, and garbage collectors. This meticulous directory architecture ensures clean separation of concerns, providing developers with a robust blueprint for mastering enterprise-grade C applications.</h6>

# PROJECT DETAILS

<details>
<summary><strong>🌀 Student Grade Management System</strong></summary>

* **Level:** Simple
* <h6><b>Description: </b>Stores student names, roll numbers, and marks using basic structures and arrays, allowing users to add records, view them, and calculate class averages.</h6>
</details>

<details>
<summary><strong>🌀 Console-Based To-Do List</strong></summary>

* **Level:** Simple
* <h6>Description: A task manager that lets users add, view, and delete daily tasks interactively, saving them to a local text file for data persistence across sessions.</h6>
</details>

<details>
<summary><strong>🌀 Interactive Contact Book</strong></summary>

* **Level:** Medium
* <h6>Description: Implements a singly linked list to dynamically manage contacts (name, phone number, and email) with features to search, update, delete, and save records using file streams.</h6>
</details>

<details>
<summary><strong>🌀 Dynamic Quiz Game</strong></summary>

* **Level:** Medium
* <h6>Description: Uses arrays of structures to load multi-question trivia games from external text files, tracking real-time scores, handling input validation, and maintaining a persistent high-score board.</h6>
</details>

<details>
<summary><strong>🌀 Banking Management System</strong></summary>

* **Level:** Medium
* <h6>Description: Simulates core financial operations (account creation, balance inquiry, deposit, and withdrawal) using structured data and binary file handling to safely read and update account records.</h6>
</details>

<details>
<summary><strong>🌀 Terminal Text Editor</strong></summary>

* **Level:** Advanced
* <h6>Description: Configures the terminal into raw mode using the POSIX `termios` API to handle low-level keyboard input, cursor navigation, real-time screen redrawing, and file editing.</h6>
</details>

<details>
<summary><strong>🌀 Single-Threaded HTTP Server</strong></summary>

* **Level:** Advanced
* <h6>Description: Utilizes Berkeley sockets (`<sys/socket.h>`) to bind to a port, accept incoming TCP connections, parse HTTP GET requests, serve static files, and respond with proper HTTP status codes.</h6>
</details>

<details>
<summary><strong>🌀 Run-Length Encoding (RLE) File Archiver</strong></summary>

* **Level:** Advanced
* <h6>Description: Performs lossless data compression and decompression on arbitrary binary files by manipulating file streams, parsing byte patterns, and implementing chunk-based headers.</h6>
</details>

<details>
<summary><strong>🌀 Mini SQL-Like Relational Database Engine</strong></summary>

* **Level:** Conceptual Capstone
* <h6>Description: A comprehensive data management project requiring a custom query lexer and parser to handle a subset of SQL commands (`CREATE TABLE`, `INSERT INTO`, `SELECT WHERE`). It features a flat-file storage engine that manages data blocks on disk, enforces basic schema definitions, and executes sequential record filtering.</h6>
</details>

<details>
<summary><strong>🌀 Custom POSIX Shell with Pipes and Redirection</strong></summary>

* **Level:** Conceptual Capstone
* <h6>Description: A fully-featured command-line interpreter built from scratch that mimics core UNIX shell behavior. It utilizes system calls like `fork()`, `execvp()`, and `waitpid()` to execute external programs, manages file descriptor manipulation for standard input/output redirection (`<`, `>`, `>>`), constructs inter-process communication pipelines (`|`), supports background job execution (`&`), and implements built-in commands like `cd` and `exit`.</h6>
</details>
